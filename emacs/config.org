* About this file

This is my Emacs configuration, written as a literate Org document. The
prose explains /why/; the =emacs-lisp= blocks are the configuration itself.

** How it is loaded

- This file (=config.org=) and its tangled output (=config.el=) live in my
  dotfiles repository on GitHub.
- Each machine has a small *stub* =init.el= in its Emacs directory that
  only loads =config.el= from the repository (see [[*The stub][The stub]]).
- Saving this file automatically *tangles* it: every =emacs-lisp= block is
  written, in order, to =config.el= (see [[*Tangle on save][Tangle on save]]).
- =config.el= is committed too, so a fresh machine (and Nix) can use it
  without running Org first. Never edit =config.el= by hand: edits are
  overwritten at the next save of this file.

** The stub

Not tangled; this is what the stub on each machine looks like. It only
loads =config.el=; the path differs per machine. Everything else,
including where Customize writes, is handled in this file.

#+begin_src emacs-lisp :tangle no
;; -*- lexical-binding: t; -*-
;; .emacs.d/init.el (the stub; not in git; path differs per machine)
(load "C:/Users/moiss/Documents/dotfiles/emacs/config.el")
#+end_src

On Windows the stub lives in =%APPDATA%\.emacs.d\init.el= (or
=~/.emacs.d/init.el=); on NixOS Home Manager writes it (see the NixOS notes
at the end).

** Two machines, one file

- *NixOS*: Nix installs Emacs, every package named in a =use-package= form,
  the tree-sitter grammars and the external tools. Nothing is downloaded.
- *Windows work laptop*: =package.el= downloads packages from GNU ELPA and
  MELPA; Scoop, uv and npm provide the external tools.

Requires Emacs 30 or newer. Blocks marked *[NixOS]* only activate where
their dependencies exist; Windows skips them.

Those blocks are wrapped in =(unless MJ-windows-p ...)= rather than using
=use-package='s =:if=: with =:if=, =use-package= still /downloads/ the
package (=:ensure= runs before =:if= is checked) and only skips configuring
it. Wrapping the whole form means Windows never installs them. Nix's
package scan finds =use-package= forms inside =unless= as well.

* Platform detection and packages

=MJ-nix-p= checks where an installed package actually lives: inside
=/nix/store= means Nix built it, so =package.el= must not download anything.

#+begin_src emacs-lisp
(defconst MJ-windows-p (eq system-type 'windows-nt)
  "Non-nil on Windows.")

(defconst MJ-nix-p
  (let ((lib (locate-library "vertico")))
    (and lib (string-prefix-p "/nix/store/" (file-truename lib))))
  "Non-nil when the Emacs packages are provided by Nix.")
#+end_src

On Windows, package signatures are checked with Scoop's native gpg rather
than the Unix-style one bundled with Git.

#+begin_src emacs-lisp
(require 'package)

(let ((gpg (and MJ-windows-p
                (substitute-in-file-name "$USERPROFILE/scoop/shims/gpg.exe"))))
  (when (and gpg (file-exists-p gpg))
    (setq epg-gpg-program gpg)))

(add-to-list 'package-archives '("melpa" . "https://melpa.org/packages/") t)
(package-initialize)          ; harmless on Nix; ensures activation elsewhere

(require 'use-package)
(setq use-package-always-ensure (not MJ-nix-p))
#+end_src

On Windows, =find= on =PATH= is Windows' own =find.exe=, an unrelated
text-search tool. Emacs (project.el, and through it eglot) expects GNU
=find= to list a project's files when the folder is not a git repository;
with the Windows one, listing fails ("FIND: Parameter format not correct")
and language servers can crash. Git for Windows ships GNU =find=, so Emacs
is pointed at it. Project-wide search (=project-find-regexp=, xref) uses
ripgrep instead of Unix =grep= on both machines.

#+begin_src emacs-lisp
(when MJ-windows-p
  (let ((gnu-find (seq-find #'file-exists-p
                            (list (substitute-in-file-name
                                   "$USERPROFILE/scoop/apps/git/current/usr/bin/find.exe")
                                  "C:/Program Files/Git/usr/bin/find.exe"))))
    (when gnu-find
      (setq find-program gnu-find))))

(setq xref-search-program 'ripgrep)
#+end_src

** Tangle on save

Saving =config.org= rewrites =config.el=. Only this file is affected; other
Org files are left alone. After tangling, =M-x eval-buffer= in =config.el=,
or =C-c C-c= on a single block here, applies changes without restarting.

#+begin_src emacs-lisp
(defun MJ-tangle-config ()
  "Tangle the configuration when `MJ-config-file' is saved."
  (when (and buffer-file-name
             (string= (file-truename buffer-file-name)
                      (file-truename MJ-config-file)))
    (org-babel-tangle)))

(add-hook 'org-mode-hook
          (lambda () (add-hook 'after-save-hook #'MJ-tangle-config nil t)))
#+end_src

* Tree-sitter

** Grammars

- *NixOS*: grammars come from Nix (home.nix); nothing to do here.
- *Windows*: install a C compiler once (=scoop install mingw=), then
  =M-x MJ-treesit-install-missing=.

If a grammar fails to load with an ABI/version error, it is newer than
this Emacs supports: add a release tag as third element of its entry and
reinstall.

#+begin_src emacs-lisp
(setq treesit-language-source-alist
      '((python     "https://github.com/tree-sitter/tree-sitter-python")
        (javascript "https://github.com/tree-sitter/tree-sitter-javascript" nil "src")
        (css        "https://github.com/tree-sitter/tree-sitter-css")
        (html       "https://github.com/tree-sitter/tree-sitter-html")
        (json       "https://github.com/tree-sitter/tree-sitter-json")
        (nix        "https://github.com/nix-community/tree-sitter-nix")))

(defun MJ-treesit-ready-p (lang)
  "Return non-nil if tree-sitter and the grammar for LANG are available."
  (and (fboundp 'treesit-available-p)
       (treesit-available-p)
       (treesit-language-available-p lang)))

(defun MJ-treesit-install-missing ()
  "Install every grammar in `treesit-language-source-alist' not yet present.
Needs git and a C compiler on PATH."
  (interactive)
  (dolist (entry treesit-language-source-alist)
    (unless (treesit-language-available-p (car entry))
      (treesit-install-language-grammar (car entry)))))
#+end_src

** Switching to tree-sitter modes

A tree-sitter mode is used only where its grammar exists, so a machine
without grammars silently keeps the classic modes. HTML stays on web-mode
(reveal.js files mix HTML, CSS and JavaScript, which =html-ts-mode= cannot
yet handle); LaTeX stays on AUCTeX.

#+begin_src emacs-lisp
(dolist (m '((python-mode     python-ts-mode python)
             (js-mode         js-ts-mode     javascript)
             (javascript-mode js-ts-mode     javascript)
             (css-mode        css-ts-mode    css)
             (js-json-mode    json-ts-mode   json)))
  (when (MJ-treesit-ready-p (nth 2 m))
    (add-to-list 'major-mode-remap-alist (cons (nth 0 m) (nth 1 m)))))
#+end_src

Hooks further down use the /base/ modes (=python-base-mode=,
=js-base-mode=, =css-base-mode=): both the classic and the tree-sitter mode
derive from them, so every setting works either way.

* Language servers (eglot)

eglot is built in and replaces lsp-mode, lsp-pyright and lsp-latex. A
helper starts eglot only when the server is actually on =PATH=, so a
machine without a given server simply skips it.

The lsp-mode indentation workaround (issue #2915, the =lsp--get-indent-width=
advice and the =tab-width= hook) is gone: eglot never drives indentation,
so web-mode's own offsets always apply.

*File watching on Windows.* Language servers can ask the editor to watch
folders for changes. basedpyright asks to watch the project /and the whole
Python installation/; on Windows eglot cannot set up that many watches,
replies with an error, and basedpyright crashes on that error ("Not
auto-reconnecting, last one didn't last long"). On Windows, eglot therefore
accepts such requests without watching. Cost: files created or renamed
outside Emacs are noticed after reopening the file or =M-x
eglot-reconnect=.

*JavaScript and TypeScript.* TypeScript 7 (July 2026) is a native rewrite
with its own language server, started as =tsc --lsp --stdio=; it no longer
ships the =tsserver.js= that the separate typescript-language-server
needs. =MJ-js-server= asks =tsc --version= when a JavaScript file is
opened and picks =tsc --lsp= for version 7 or later, and
typescript-language-server for older versions (for example an older
package set on NixOS). Installing =typescript= (=npm install -g
typescript=) is enough on Windows.

*Unsupported optional features.* Some servers offer features eglot does
not support, and eglot warns about each ("Server tried to register
unsupported capability ..."). Two such offers are accepted silently: the
HTML server's =workspace/didChangeWorkspaceFolders= (tracking several
project folders; one is all I need) and TypeScript 7's
=workspace/didChangeConfiguration= (eglot sends its settings at startup
anyway).

*Mode-line indicator.* eglot's indicator uses a green that is unreadable
with deeper-blue; it now uses the mode line's own emphasis style.

*Type-checking level.* basedpyright's default mode is strict: it warns
about every missing type annotation, which is noise for beginners' code
and teaching material. "standard" matches plain pyright. Switch per project
with a =[tool.basedpyright]= section in =pyproject.toml= if wanted.

#+begin_src emacs-lisp
(defun MJ-eglot-ensure-if (program)
  "Return a hook function that starts eglot only if PROGRAM is on PATH."
  (lambda ()
    (when (executable-find program)
      (eglot-ensure))))

(defun MJ-js-server (&optional _interactive)
  "Return the command for the JavaScript/TypeScript language server.
TypeScript 7 and later contain their own server (`tsc --lsp --stdio');
older versions need the separate typescript-language-server."
  (let ((version (ignore-errors (car (process-lines "tsc" "--version")))))
    (if (and version
             (string-match "Version \\([0-9]+\\)" version)
             (>= (string-to-number (match-string 1 version)) 7))
        '("tsc" "--lsp" "--stdio")
      '("typescript-language-server" "--stdio"))))

(use-package eglot
  :ensure nil
  :bind (:map eglot-mode-map
              ("C-c r" . eglot-rename)          ; same key as with lsp-mode
              ("C-c a" . eglot-code-actions))
  :custom (eglot-autoshutdown t)
  :config
  (add-to-list 'eglot-server-programs
               '((python-mode python-ts-mode) . ("basedpyright-langserver" "--stdio")))
  (add-to-list 'eglot-server-programs
               '((web-mode :language-id "html") . ("vscode-html-language-server" "--stdio")))
  (add-to-list 'eglot-server-programs
               '((LaTeX-mode :language-id "latex") . ("texlab")))
  (add-to-list 'eglot-server-programs
               '(nix-ts-mode . ("nil")))
  ;; [Windows] Accept file-watch requests without watching (see above).
  (when MJ-windows-p
    (cl-defmethod eglot-register-capability
      (_server (_method (eql 'workspace/didChangeWatchedFiles)) _id &rest _)
      "Ignore file-watching requests on Windows."
      nil))
  ;; JavaScript/TypeScript: the server is chosen when a file is opened
  ;; (see MJ-js-server above).
  (add-to-list 'eglot-server-programs
               '(((js-mode            :language-id "javascript")
                  (js-ts-mode         :language-id "javascript")
                  (tsx-ts-mode        :language-id "typescriptreact")
                  (typescript-ts-mode :language-id "typescript")
                  (typescript-mode    :language-id "typescript"))
                 . MJ-js-server))
  ;; Accept, silently, two optional features some servers offer but eglot
  ;; does not need (see above).
  (cl-defmethod eglot-register-capability
    (_server (_method (eql 'workspace/didChangeWorkspaceFolders)) _id &rest _)
    "Ignore workspace-folder registration (single-folder projects)."
    nil)
  (cl-defmethod eglot-register-capability
    (_server (_method (eql 'workspace/didChangeConfiguration)) _id &rest _)
    "Ignore configuration-change registration (eglot sends settings anyway)."
    nil)
  ;; Readable eglot indicator in the mode line, whatever the theme.
  (set-face-attribute 'eglot-mode-line nil :inherit 'mode-line-emphasis))

;; basedpyright: "standard" type checking instead of its strict default.
(setq-default eglot-workspace-configuration
              '(:basedpyright (:analysis (:typeCheckingMode "standard"))))

(add-hook 'python-base-mode-hook (MJ-eglot-ensure-if "basedpyright-langserver"))
(add-hook 'js-base-mode-hook     (MJ-eglot-ensure-if "tsc"))
(add-hook 'css-base-mode-hook    (MJ-eglot-ensure-if "vscode-css-language-server"))
(add-hook 'web-mode-hook         (MJ-eglot-ensure-if "vscode-html-language-server"))
(add-hook 'LaTeX-mode-hook       (MJ-eglot-ensure-if "texlab"))
(add-hook 'nix-ts-mode-hook      (MJ-eglot-ensure-if "nil"))

* Formatting (Apheleia)

Apheleia formats buffers on save: ruff for Python (replacing black: same
style, much faster), Prettier for HTML/CSS/JS. It replaced blacken and
prettier-js; prettier-js never worked reliably on Windows here, for reasons
that weren't pinned down.

*How it works.* Apheleia sends the buffer's contents to the formatter in
the background, then runs the external =diff= program to compare the
original and formatted text, and applies only the changes. This keeps
point, marks and undo history intact, and skips the update if you edited
the buffer in the meantime.

*External requirements* (all on =exec-path=):
- =diff= (on Windows: Scoop's diffutils or Git's =usr/bin=);
- =bash= on Windows, because Apheleia runs Prettier through a bundled bash
  script, "apheleia-npx" (Git for Windows' bash works);
- Prettier (=npm install -g prettier=) and ruff (=uv tool install ruff=;
  on NixOS from home.nix).

*Troubleshooting.* Apheleia fails silently. If saving doesn't format, run
=M-x apheleia-goto-error= right after saving to see the formatter's output.
Prettier honours =.prettierignore= files in the project and its parent
folders; a project-level one (e.g. reveal.js's own, which excludes all
=*.html=) makes Prettier report success while changing nothing. Check with
=prettier --file-info <file>=.

#+begin_src emacs-lisp
(use-package apheleia
  :hook ((python-base-mode js-base-mode css-base-mode web-mode) . apheleia-mode)
  :config

#+end_src

* LaTeX

*Master file.* =TeX-master t= treats every =.tex= file as a stand-alone
document, so AUCTeX never asks which file to compile. For a multi-file
project (chapters =\input= into =main.tex=), open each chapter and press
=C-c _= once to name its master file; AUCTeX stores that in a small comment
block at the end of the chapter. Compiling a chapter without it fails with

CDLaTeX gives very fast maths input (=`a= → =\alpha=, quick fractions
and environments), in LaTeX and in Org.

CDLaTeX binds =TAB= to its own command (jumping out of braces, expanding
its templates), which hides yasnippet's =TAB=. CDLaTeX offers a hook that
runs first on =TAB=: =MJ-yas-expand-maybe= tries to expand a snippet there
and only lets CDLaTeX continue when there is none. Inside an expanded
snippet, =TAB= still jumps between its fields.

#+begin_src emacs-lisp
(defun MJ-yas-expand-maybe ()
  "Expand a yasnippet before point; return non-nil if one was expanded.
Used in `cdlatex-tab-hook' so snippets work in LaTeX buffers."
  (when (bound-and-true-p yas-minor-mode)
    (let ((yas-fallback-behavior 'return-nil))
      (yas-expand))))

*Removing a list item.* Org renumbers a list when items are moved
(=M-<up>=, =M-<down>=) but not when one is killed; that needed a =C-c
C-c= afterwards. =C-c k= kills the item the cursor is in (anywhere on any
of its lines, sub-items included) and renumbers the list, fixing
checkbox counters like =[1/3]= too. =C-u C-c k= deletes it without
saving it to the kill ring. The kill ring gets the item without its
bullet, so =M-RET= then =C-y= elsewhere moves it with a correct bullet.
It uses Org's own list functions, the ones behind =M-<up>= and
=M-<down>=; Org has no built-in command for this (checked up to 9.8).

#+begin_src emacs-lisp
(defun MJ-org-kill-list-item (&optional delete)
  "Kill the list item at point, sub-items included, and renumber the list.
With a prefix argument, DELETE the item instead of saving it to the kill ring."
  (interactive "P")
  (let ((item (or (org-in-item-p) (user-error "Not in a list item"))))
    (goto-char item)
    (let ((struct (org-list-send-item item (if delete 'delete 'kill)
                                      (org-list-struct))))
      (org-list-write-struct struct (org-list-parents-alist struct))
      (org-update-checkbox-count-maybe))))

(with-eval-after-load 'org
  (define-key org-mode-map (kbd "C-c k") #'MJ-org-kill-list-item))
#+end_src

* Customize settings (loaded last)

Settings saved through =M-x customize= live in =custom.el= (see
[[*Platform detection and packages][Platform detection and packages]]).
Loading it after everything else means a Customize choice overrides the
value set above. This used to happen in the stub; doing it here keeps
every stub, including the one Home Manager writes, a single line.

One exception needs care: =custom.el= also stores
=package-selected-packages=, the list of packages I chose to install. When
=use-package= installs a new package during startup, it adds it to that
list in memory; loading =custom.el= afterwards would replace the list with
the older saved copy, and =package-autoremove= would then offer to delete
the new package. So the two lists are merged instead of overwritten.

#+begin_src emacs-lisp
(let ((installed-this-session package-selected-packages))
  (load custom-file 'noerror 'nomessage)
  (setq package-selected-packages
        (delete-dups (append installed-this-session package-selected-packages))))
#+end_src
