* About this file

This one Org file is the *source* of my whole configuration: the NixOS
system, my Home Manager user configuration, niri's settings and my Emacs
configuration. The prose explains /why/; the code blocks are the
configuration itself. Saving the file *tangles* it: every code block is
written to the file named in its =:tangle= setting, in document order.

The output is the ordinary modular layout below, so Nix, niri and Emacs
never notice that the files were generated. The installer uses those files
too: you do not need Emacs (or this file) to install a machine.

** What it produces

|-----------------------------------+---------------------------------------+----------------------------------|

Every generated file starts with a line saying it was generated from
here. *Never edit a generated file*: the next save of this file
overwrites it. Edit the block here instead.

** What is not in here

- =nixos/hosts/<machine>/hardware-configuration.nix=: written by the
  installer (=nixos-generate-config=) for each machine's disks and
  hardware. It is copied into the repository and committed, but never
  edited by hand.
- =flake.lock=: written by Nix; pins every input. Committed.
- =README.md= and =.gitattributes=: short, rarely changed, edited directly.
- Secrets: passwords, tokens and keys never go into this file or into git
  (they live in the keyring; see the PDF, chapter 12).

** How it is used

1. =C-c i= in Emacs opens this file (see [[*Opening it][Opening it]]).
2. Edit a block; =C-c '= edits it in its own language mode.
3. Save. Emacs tangles the file: all generated files are rewritten (see
   [[*Tangle on save][Tangle on save]]). Without Emacs open, the shell
   command =tangle= does the same.
4. Apply the change:
   - Nix files: =rebuild= (=nh os switch=).
   - niri: nothing; niri reloads its settings as soon as the file changes.
   - Emacs: =M-x eval-buffer= in =config.el=, or restart the daemon; after
     adding a package, =rebuild= first (Nix installs it).
5. Commit this file *and* the generated files together (Magit: =C-x g=,
   stage all, commit, push). A flake only sees files that git tracks, and
   another machine (or a fresh install) uses the generated files without
   tangling.

** Conventions

- Each top-level section sets the file its blocks go to, in a property
  drawer (=:header-args:nix: :tangle home/shell.nix=). Blocks inherit it.
- Emacs Lisp blocks go to =emacs/config.el= unless they say otherwise
  (set at the top of this file).
- *Package lists are assembled from pieces.* A block with
  =:noweb-ref apps= is not written anywhere by itself; the line =<<apps>>=
  in another block (with =:noweb yes=) is replaced by all =apps= pieces,
  in document order and with the same indentation. That lets the Nix
  packages an Emacs feature needs sit next to the Emacs Lisp that uses
  them (see for example [[*Python][Python]]).

** Outputs: one system per machine

=mkHost= builds a machine from the shared system configuration plus that
machine's folder in =nixos/hosts/=. Adding a machine is one line here and
one section under [[*Machines][System → Machines]].

#+begin_src nix
  outputs =
    { nixpkgs, ... }@inputs:
    let
      username = "mathijs"; # your login name; change it before installing

      # One function builds every machine: the shared configuration plus the
      # machine's own folder in nixos/hosts/.
      mkHost =
        hostName:
        nixpkgs.lib.nixosSystem {
          specialArgs = { inherit inputs username hostName; };
          modules = [
            ./nixos/configuration.nix
            ./nixos/hosts/${hostName}
          ];
        };
    in
    {
      nixosConfigurations = {
        # The USB test installation on the HP EliteBook:
        #   sudo nixos-rebuild switch --flake ~/dotfiles#nixusb   (or: nh os switch)
        nixusb = mkHost "nixusb";

        # The new laptop, once nixos/hosts/laptop/ exists (chapter 19.8):
        # laptop = mkHost "laptop";
      };
    };
}
#+end_src

#+begin_src nix
# GENERATED from config.org ("System (NixOS) / Machines / nixusb"). Do not edit; edit config.org.
# nixos/hosts/nixusb/default.nix: settings for the USB test installation
# only. Each machine gets a folder like this one (chapter 19.8).
{ hostName, ... }:

{
  imports = [
    ./hardware-configuration.nix # generated by nixos-generate-config; copy it in
  ];

  networking.hostName = hostName; # "nixusb", from flake.nix

  # Boot loader on a USB disk: do NOT write boot entries into the laptop's
  # firmware (that is where Windows's entry lives). systemd-boot still
  # installs itself as the removable-media fallback (EFI/BOOT/BOOTX64.EFI),
  # so the stick boots from the firmware's one-time boot menu (Esc, F9 on HP).
  boot.loader.efi.canTouchEfiVariables = false;

  # Make sure the USB disk can be found early in boot on any machine.
  boot.initrd.availableKernelModules = [
    "xhci_pci"
    "usb_storage"
    "uas"
    "sd_mod"
  ];

  # Fewer writes to the USB disk: don't record when files were last read.
  fileSystems."/".options = [ "noatime" ];

# The built-in keyboard of this HP is broken: one Ctrl key sometimes
# "sticks" (a press without a release), which turns m into Enter and
# i into Tab on text screens. Make Linux ignore that key.
services.udev.extraHwdb = ''
  evdev:atkbd:dmi:*
   KEYBOARD_KEY_1d=reserved
 '';
 }
#+end_src

#+begin_src nix
let

  # open, otherwise start the command. Used by niri's Mod+B (chapter 4.3).
  run-or-raise = pkgs.writeShellApplication {
    name = "run-or-raise";
    runtimeInputs = [ pkgs.jq ];
    text = ''
      app="$1"; shift
      id=$(niri msg --json windows \
        | jq -r --arg app "$app" 'first(.[] | select(.app_id == $app) | .id) // empty')
      if [ -n "$id" ]; then
        niri msg action focus-window --id "$id"
      else
        exec "$@"
      fi
    '';
  };

    name = "power-menu";

        | fuzzel --dmenu --prompt "power: " --lines 5 --width 20) || exit 0
      case "$choice" in
        lock) loginctl lock-session ;;
        suspend) systemctl suspend ;;
        logout) niri msg action quit --skip-confirmation ;;
        reboot) systemctl reboot ;;
        poweroff) systemctl poweroff ;;
      esac
    '';
  };
in

* Emacs: emacs/config.el

Every =emacs-lisp= block below is written to =emacs/config.el=, in this
order. The same =config.el= runs on NixOS and on the Windows work laptop.

** About the Emacs configuration

My Emacs configuration. The prose explains /why/; the =emacs-lisp= blocks
are the configuration itself. They all go to =emacs/config.el= (set at the
top of this file). A few =nix= blocks in between name the external tools
a feature needs; they are pieces of the package list in
[[*Development tools: home/dev.nix][home/dev.nix]] and do not end up in
=config.el=.

*** How it is loaded

- This file (=config.org=, at the top of the dotfiles repository) and its
  tangled output (=emacs/config.el=) live in my dotfiles repository on
  GitHub.
- Each machine has a small *stub* =init.el= in its Emacs directory that
  only loads =config.el= from the repository (see [[*The stub][The stub]]).
- Saving this file automatically *tangles* it: every =emacs-lisp= block is
  written, in order, to =emacs/config.el=, and the Nix and niri blocks to
  their files (see [[*Tangle on save][Tangle on save]]).
- =config.el= is committed too, so a fresh machine (and Nix) can use it
  without running Org first. Never edit =config.el= by hand: edits are
  overwritten at the next save of this file.

*** The stub

Not tangled; this is what the stub on each machine looks like. It only
loads =emacs/config.el=; the path differs per machine. Everything else,
including where Customize writes, is handled in this file. The stub does
not change now that =config.org= has moved to the top of the repository:
it points at =config.el=, which stayed where it was.

#+begin_src emacs-lisp :tangle no
;; -*- lexical-binding: t; -*-
;; .emacs.d/init.el (the stub; not in git; path differs per machine)
(load "C:/Users/moiss/Documents/dotfiles/emacs/config.el")
#+end_src

On Windows the stub lives in =%APPDATA%\.emacs.d\init.el= (or
=~/.emacs.d/init.el=); on NixOS Home Manager writes it (see
[[*Emacs packaging: home/emacs.nix][Emacs packaging]]).

*** Two machines, one file

- *NixOS*: Nix installs Emacs, every package named in a =use-package= form,
  the tree-sitter grammars and the external tools (the =dev-tools= pieces
  in this section). Nothing is downloaded.
- *Windows work laptop*: =package.el= downloads packages from GNU ELPA and
  MELPA; Scoop, uv and npm provide the external tools.

Requires Emacs 30 or newer. Blocks marked *[NixOS]* only activate where
their dependencies exist; Windows skips them.

Those blocks are wrapped in =(unless MJ-windows-p ...)= rather than using
=use-package='s =:if=: with =:if=, =use-package= still /downloads/ the
package (=:ensure= runs before =:if= is checked) and only skips configuring
it. Wrapping the whole form means Windows never installs them. Nix's
package scan finds =use-package= forms inside =unless= as well.

** Language servers (eglot)

eglot is built in and replaces lsp-mode, lsp-pyright and lsp-latex. A
helper starts eglot only when the server is actually on =PATH=, so a
machine without a given server simply skips it.

The lsp-mode indentation workaround (issue #2915, the =lsp--get-indent-width=
advice and the =tab-width= hook) is gone: eglot never drives indentation,
so web-mode's own offsets always apply.

*File watching on Windows.* Language servers can ask the editor to watch
folders for changes. basedpyright asks to watch the project /and the whole
Python installation/; on Windows eglot cannot set up that many watches,
replies with an error, and basedpyright crashes on that error ("Not
auto-reconnecting, last one didn't last long"). On Windows, eglot therefore
accepts such requests without watching. Cost: files created or renamed
outside Emacs are noticed after reopening the file or =M-x
eglot-reconnect=.

*JavaScript and TypeScript.* TypeScript 7 (July 2026) is a native rewrite
with its own language server, started as =tsc --lsp --stdio=; it no longer
ships the =tsserver.js= that the separate typescript-language-server
needs. =MJ-js-server= asks =tsc --version= when a JavaScript file is
opened and picks =tsc --lsp= for version 7 or later, and
typescript-language-server for older versions (for example an older
package set on NixOS). Installing =typescript= (=npm install -g
typescript=) is enough on Windows.

*Unsupported optional features.* Some servers offer features eglot does
not support, and eglot warns about each ("Server tried to register
unsupported capability ..."). Two such offers are accepted silently: the
HTML server's =workspace/didChangeWorkspaceFolders= (tracking several
project folders; one is all I need) and TypeScript 7's
=workspace/didChangeConfiguration= (eglot sends its settings at startup
anyway).

*Mode-line indicator.* eglot's indicator uses a green that is unreadable
with deeper-blue; it now uses the mode line's own emphasis style.

*Type-checking level.* basedpyright's default mode is strict: it warns
about every missing type annotation, which is noise for beginners' code
and teaching material. "standard" matches plain pyright. Switch per project
with a =[tool.basedpyright]= section in =pyproject.toml= if wanted.

** Formatting (Apheleia)

Apheleia formats buffers on save: ruff for Python (replacing black: same
style, much faster), Prettier for HTML/CSS/JS. It replaced blacken and
prettier-js; prettier-js never worked reliably on Windows here, for reasons
that weren't pinned down.

*How it works.* Apheleia sends the buffer's contents to the formatter in
the background, then runs the external =diff= program to compare the
original and formatted text, and applies only the changes. This keeps
point, marks and undo history intact, and skips the update if you edited
the buffer in the meantime.

*External requirements* (all on =exec-path=):
- =diff= (on Windows: Scoop's diffutils or Git's =usr/bin=);
- =bash= on Windows, because Apheleia runs Prettier through a bundled bash
  script, "apheleia-npx" (Git for Windows' bash works);
- Prettier (=npm install -g prettier=) and ruff (=uv tool install ruff=;
  on NixOS from home.nix).

*Troubleshooting.* Apheleia fails silently. If saving doesn't format, run
=M-x apheleia-goto-error= right after saving to see the formatter's output.
Prettier honours =.prettierignore= files in the project and its parent
folders; a project-level one (e.g. reveal.js's own, which excludes all
=*.html=) makes Prettier report success while changing nothing. Check with
=prettier --file-info <file>=.

*Removing a list item.* Org renumbers a list when items are moved
(=M-<up>=, =M-<down>=) but not when one is killed; that needed a =C-c
C-c= afterwards. =C-c k= kills the item the cursor is in (anywhere on any
of its lines, sub-items included) and renumbers the list, fixing
checkbox counters like =[1/3]= too. =C-u C-c k= deletes it without
saving it to the kill ring. The kill ring gets the item without its
bullet, so =M-RET= then =C-y= elsewhere moves it with a correct bullet.
It uses Org's own list functions, the ones behind =M-<up>= and
=M-<down>=; Org has no built-in command for this (checked up to 9.8).

#+begin_src emacs-lisp
(defun MJ-org-kill-list-item (&optional delete)
  "Kill the list item at point, sub-items included, and renumber the list.
With a prefix argument, DELETE the item instead of saving it to the kill ring."
  (interactive "P")
  (let ((item (or (org-in-item-p) (user-error "Not in a list item"))))
    (goto-char item)
    (let ((struct (org-list-send-item item (if delete 'delete 'kill)
                                      (org-list-struct))))
      (org-list-write-struct struct (org-list-parents-alist struct))
      (org-update-checkbox-count-maybe))))

(with-eval-after-load 'org
  (define-key org-mode-map (kbd "C-c k") #'MJ-org-kill-list-item))
#+end_src

** Customize settings (loaded last)

Settings saved through =M-x customize= live in =custom.el= (see
[[*Platform detection and packages][Platform detection and packages]]).
Loading it after everything else means a Customize choice overrides the
value set above. This used to happen in the stub; doing it here keeps
every stub, including the one Home Manager writes, a single line.

One exception needs care: =custom.el= also stores
=package-selected-packages=, the list of packages I chose to install. When
=use-package= installs a new package during startup, it adds it to that
list in memory; loading =custom.el= afterwards would replace the list with
the older saved copy, and =package-autoremove= would then offer to delete
the new package. So the two lists are merged instead of overwritten.

#+begin_src emacs-lisp
(let ((installed-this-session package-selected-packages))
  (load custom-file 'noerror 'nomessage)
  (setq package-selected-packages
        (delete-dups (append installed-this-session package-selected-packages))))
#+end_src
