* About this file

This one Org file is the *source* of my whole configuration: every program
on my machines, how it is set up, and why. The prose explains; the code
blocks are the configuration. Saving the file *tangles* it: every code block
is written to the file named in its =:tangle= setting, in document order.
Nothing reads this file except Org; the programs read the generated files,
which are committed to git together with it. The =#+DATE= line at the top
is set to today's date whenever the file is saved in Emacs (at home, at
work or on NixOS), so it shows at a glance how recent a copy is; =git log=
has the full history.

** The three layers

Every generated file lands in one of two folders, and that decides what a
change costs. Everything else a program keeps is /state/, which is not
configuration and is not in the repository.

| Layer | Folder                 | Read by                               | A change takes effect                        |
|-------+------------------------+---------------------------------------+----------------------------------------------|
| Nix   | =flake.nix=, =nix/=    | Nix, when the system is rebuilt       | after =rebuild=                              |
| Live  | =live/=                | the programs, through links in =~=    | at once, or the next time the program starts |
| State | (not in the repository) | the programs, which write it themselves | not configuration; see the last chapter     |

The rule: *Nix decides what exists and where it is linked; the live files
say what the programs do.* Adding a program, a link, an Emacs package, a
TeX package, a font or a game needs a rebuild. Changing a key binding, a
colour, an alias, the LaTeX preamble or the Emacs configuration does not.

** Daily workflow

1. Open this file: =C-c i= in Emacs, or =cfg= in a terminal.
2. Edit. =C-c '= edits a code block in its own mode.
3. Save. Emacs then
   - writes every generated file;
   - deletes generated files whose section no longer exists;
   - stages the generated files in git, so Nix can see new ones;
   - says /Nothing to rebuild/ or /Nix files changed: run rebuild/, and
     checks niri's settings.
4. If asked: =rebuild=. The bar shows "rebuild" until you do.
5. Commit this file together with the staged files (Magit: =C-x g=, =s= on
   =config.org=, =c c=), and push.

Without Emacs, the command =tangle-config= does step 3.

=C-c C-c= runs only Emacs Lisp blocks here (=:eval no= for the others): a
Nix, KDL or shell block is a fragment of a file, not a program.

** Conventions

- *One heading per program.* Its property drawer names where its blocks
  go: a Nix module in =nix/<role>/= and the program's own files in
  =live/<program>/=.
- *Roles.* =nix/core/= is for every machine, =nix/desktop/= for the laptop
  and the USB stick, =nix/server/= for the home server. Every =.nix= file in
  those folders is imported automatically; there are no import lists.
- *Links.* A program's Nix module also says which live files appear in the
  home folder: ~dotfiles.links.".config/foo/foo.ini" = "live/foo/foo.ini";~.
- *GENERATED.* Every generated file starts with a line saying where it
  comes from. Never edit a generated file: the next save overwrites it.
  The clean-up after saving only ever deletes files that carry this line.
- *Noweb.* Values used in several places (the NixOS release, the colours,
  the fonts) are named once in [[*Shared values][Shared values]] and inserted with
  =<<name>>=. Lists assembled from pieces (the tools the Emacs sections
  need) use =:noweb-ref=.

** What is not in here

- =nix/hosts/<machine>/hardware-configuration.nix=: written by the
  installer for each machine's disks and hardware; committed, never edited.
- =flake.lock=: written by Nix; pins every input. Committed; updated by the
  weekly job (see [[*Weekly updates: nix/core/updates.nix][Weekly updates]]).
- =README.md= and =.gitattributes=: short, edited directly.
- Secrets: passwords, tokens and keys live in the keyring and in program
  folders, never here.
- State: browser profiles, mail, saved games, the torrent list. The last
  chapter, [[*State: what is not in this file][State]], lists where each lives.

*** Outputs: machines and roles

=mkHost= builds a machine from three things:

1. every =.nix= file in =nix/core/= (what every machine needs);
2. every =.nix= file in the folders of the machine's /roles/
   (=nix/desktop/=, =nix/server/=);
3. the machine's own folder, =nix/hosts/<name>/=.

=nixFilesIn= finds the files. It only uses Nix's built-in functions, so it
works before nixpkgs is even loaded. Because every file is found
automatically, adding a program is adding a section to this file; there is
no list of imports to keep up to date. The other side of that: a file that
should no longer be used must disappear, which is what the clean-up after
saving does (see [[*Tangling, cleaning up and staging: live/emacs/dotfiles-tangle.el][Tangling, cleaning up and staging]]).

=specialArgs= are extra values every module can ask for by name: the
flake's inputs, your login name and the machine's name.

#+begin_src nix
  outputs =
    { nixpkgs, ... }@inputs:
    let
      username = "<<username>>";

      # Every .nix file below DIR, in alphabetical order.
      nixFilesIn =
        dir:
        let
          entries = builtins.readDir dir;
        in
        builtins.concatMap (
          name:
          let
            path = dir + "/${name}";
            type = entries.${name};
          in
          if type == "directory" then
            nixFilesIn path
          else if type == "regular" && builtins.match ".*\\.nix" name != null then
            [ path ]
          else
            [ ]
        ) (builtins.attrNames entries);

      # A machine: the core, the folders of its roles, and its own folder.
      mkHost =
        hostName: roles:
        nixpkgs.lib.nixosSystem {
          specialArgs = { inherit inputs username hostName; };
          modules =
            nixFilesIn ./nix/core
            ++ builtins.concatMap (role: nixFilesIn (./nix + "/${role}")) roles
            ++ [ ./nix/hosts/${hostName} ];
        };
    in
    {
      nixosConfigurations = {
        # The USB test installation (on the EliteBook):
        #   rebuild          (or: nh os switch ~/dotfiles -H nixusb)
        nixusb = mkHost "nixusb" [ "desktop" ];

        # The new laptop: install with  nixos-install --flake .#laptop
        laptop = mkHost "laptop" [ "desktop" ];

        # The EliteBook as home server, once its fan is repaired:
        # server = mkHost "server" [ "server" ];
      };
    };
}
#+end_src

** Links, seeds and folders: nix/core/links.nix
:PROPERTIES:
:header-args:nix: :tangle nix/core/links.nix
:END:

Three lists connect the live files to the home folder. Each program's Nix
module adds to them; this module collects them and hands them to a small
program, =dotfiles-link=, which makes the home folder match.

| Option             | Example                                                       | What happens                                        |
|--------------------+---------------------------------------------------------------+-----------------------------------------------------|
| =dotfiles.links=   | ~".config/niri/config.kdl" = "live/niri/config.kdl";~         | =~/.config/niri/config.kdl= becomes a link to the file in the repository |
| =dotfiles.seeds=   | ~".config/app/app.ini" = "live/app/app.ini";~                 | the file is *copied* once, if nothing is there yet; after that it is the program's |
| =dotfiles.folders= | ~[ "Pictures/Screenshots" ]~                                  | the folder is created                               |

*Links* are for files a program only reads: edit the file here, save, and
the program sees the new version. *Seeds* are for programs that rewrite
their own settings (a game, a GUI program's options dialog): a link would
let the program write into the repository, so they get a starting copy
instead.

=dotfiles-link= runs as you, through NixOS's =system.userActivationScripts=:
at every rebuild and every time you log in. It keeps a list of the links it
made, in =~/.local/state/dotfiles/links=, so it can tidy up:

- a link that the configuration no longer lists is *removed*, but only if
  it still points into =~/dotfiles= (it never touches anything else);
- a real file or folder where a link should go is *moved aside* to
  =<name>.before-dotfiles=, never deleted;
- a link whose source does not exist yet (the repository is not cloned) is
  skipped with a message, and made at the next run.

#+begin_src nix
# GENERATED from config.org ("Foundations / Links, seeds and folders"). Do not edit; edit config.org.
# nix/core/links.nix: the options dotfiles.links, dotfiles.seeds and
# dotfiles.folders, and the program that applies them to your home folder.
{
  config,
  lib,
  pkgs,
  username,
  ...
}:

let
  cfg = config.dotfiles;
  repo = "/home/${username}/dotfiles";

  # One line per entry: KIND <tab> TARGET <tab> SOURCE
  manifest = pkgs.writeText "dotfiles-manifest" (
    lib.concatStrings (
      map (dir: "folder\t${dir}\t-\n") cfg.folders
      ++ lib.mapAttrsToList (target: source: "seed\t${target}\t${repo}/${source}\n") cfg.seeds
      ++ lib.mapAttrsToList (target: source: "link\t${target}\t${repo}/${source}\n") cfg.links
    )
  );

  linker = pkgs.writeShellApplication {
    name = "dotfiles-link";
    runtimeInputs = [
      pkgs.coreutils
      pkgs.gnugrep
    ];
    text = builtins.readFile ./dotfiles-link.sh;
  };
in
{
  options.dotfiles = {
    links = lib.mkOption {
      type = lib.types.attrsOf lib.types.str;
      default = { };
      description = "Home-relative path -> repository-relative path: made a link.";
    };
    seeds = lib.mkOption {
      type = lib.types.attrsOf lib.types.str;
      default = { };
      description = "Home-relative path -> repository-relative path: copied once.";
    };
    folders = lib.mkOption {
      type = lib.types.listOf lib.types.str;
      default = [ ];
      description = "Home-relative folders to create.";
    };
  };

  config = {
    # Runs as each user, at every activation (rebuild) and at every login.
    system.userActivationScripts.dotfiles = ''
      if [ "$(${pkgs.coreutils}/bin/id -un)" = ${lib.escapeShellArg username} ]; then
        ${linker}/bin/dotfiles-link ${manifest} || echo "dotfiles-link failed" >&2
      fi
    '';

    # Also available by hand:  dotfiles-link /etc/dotfiles-manifest
    environment.systemPackages = [ linker ];
    environment.etc."dotfiles-manifest".source = manifest;
  };
}
#+end_src

*** The linker: nix/core/dotfiles-link.sh

Read by the Nix block above (=builtins.readFile=), which turns it into the
command =dotfiles-link=; =writeShellApplication= checks it with ShellCheck
when the system is built and runs it with =errexit=, =nounset= and
=pipefail=.

#+begin_src sh :tangle nix/core/dotfiles-link.sh
# GENERATED from config.org ("Foundations / Links, seeds and folders"). Do not edit; edit config.org.
# dotfiles-link MANIFEST: make the home folder match MANIFEST, a list
# written by Nix with one line per entry:  KIND <tab> TARGET <tab> SOURCE
#   folder TARGET -       create the folder ~/TARGET
#   seed   TARGET SOURCE  copy SOURCE to ~/TARGET once, if nothing is there
#   link   TARGET SOURCE  make ~/TARGET a link to SOURCE
# Links made by an earlier run that the manifest no longer lists are
# removed, as long as they still point into ~/dotfiles.

manifest=$1
repo="$HOME/dotfiles"
state="${XDG_STATE_HOME:-$HOME/.local/state}/dotfiles"
mkdir -p "$state"
made=$(mktemp)
trap 'rm -f "$made"' EXIT

while IFS=$'\t' read -r kind target source; do
  dest="$HOME/$target"
  case "$kind" in
    folder)
      mkdir -p "$dest"
      ;;
    seed)
      if [ ! -e "$dest" ] && [ ! -L "$dest" ] && [ -e "$source" ]; then
        mkdir -p "$(dirname "$dest")"
        cp -R --no-preserve=mode,ownership "$source" "$dest"
        echo "dotfiles: copied ~/$target (yours to change from now on)"
      fi
      ;;
    link)
      if [ ! -e "$source" ]; then
        echo "dotfiles: skipped ~/$target: $source does not exist" >&2
        continue
      fi
      if [ "$(readlink "$dest" || true)" != "$source" ]; then
        if [ -L "$dest" ]; then
          rm "$dest"
        elif [ -e "$dest" ]; then
          backup="$dest.before-dotfiles"
          if [ -e "$backup" ]; then
            backup="$backup.$(date +%Y%m%d%H%M%S)"
          fi
          mv "$dest" "$backup"
          echo "dotfiles: moved the existing ~/$target to $backup"
        fi
        mkdir -p "$(dirname "$dest")"
        ln -s "$source" "$dest"
        echo "dotfiles: linked ~/$target"
      fi
      printf '%s\n' "$target" >> "$made"
      ;;
  esac
done < "$manifest"

# Links from an earlier run that are no longer wanted.
if [ -f "$state/links" ]; then
  while IFS= read -r target; do
    dest="$HOME/$target"
    if [ -L "$dest" ] && ! grep -qxF -- "$target" "$made"; then
      case "$(readlink "$dest")" in
        "$repo"/*)
          rm "$dest"
          echo "dotfiles: removed ~/$target (no longer in config.org)"
          ;;
      esac
    fi
  done < "$state/links"
fi
sort -u "$made" > "$state/links"
#+end_src

** Rebuild status

Three small commands in =live/bin/= (linked into =~/.local/bin=, which
NixOS puts on the =PATH=; see [[*Shell: nix/core/shell.nix][Shell]]). Together they answer "does the
running system match my configuration?":

- =dotfiles-fingerprint= prints one checksum over everything Nix reads
  (=flake.nix= and =nix/=, as git knows them);
- =rebuild= rebuilds through nh and, when that succeeds, writes the
  fingerprint to =~/.local/state/dotfiles/built=;
- =dotfiles-status= compares the two for the bar, and also reports a new
  NixOS release (see [[*Weekly updates: nix/core/updates.nix][Weekly updates]]). Saving this file in Emacs asks the
  same question.

=flake.lock= is deliberately not part of the fingerprint: the weekly update
changes it and builds the result itself.

#+begin_src sh :tangle live/bin/dotfiles-fingerprint :tangle-mode o755
#!/usr/bin/env bash
# GENERATED from config.org ("Foundations / Rebuild status"). Do not edit; edit config.org.
# dotfiles-fingerprint: one checksum over everything Nix reads (flake.nix and
# nix/, as git knows them). Equal fingerprints mean equal configurations.
set -euo pipefail
cd "$HOME/dotfiles"
git ls-files -z -- flake.nix nix | sort -z | xargs -0 cat -- | sha256sum | cut -d' ' -f1
#+end_src

=rebuild= takes nh's subcommands: =rebuild= (=switch=: build, activate, make
it the boot default), =rebuild boot= (from the next boot on), =rebuild test=
(activate, but not for the next boot), =rebuild build= (only build). Extra
options pass through: =rebuild switch --update= (the alias =update=) first
updates every input.

#+begin_src sh :tangle live/bin/rebuild :tangle-mode o755
#!/usr/bin/env bash
# GENERATED from config.org ("Foundations / Rebuild status"). Do not edit; edit config.org.
# rebuild [switch|boot|test|build] [nh options]: rebuild through nh, then
# remember what was built (see dotfiles-fingerprint and dotfiles-status).
set -euo pipefail
mode=switch
case "${1:-}" in
  switch | boot | test | build)
    mode=$1
    shift
    ;;
esac
nh os "$mode" "$@"
if [ "$mode" != build ]; then
  state="${XDG_STATE_HOME:-$HOME/.local/state}/dotfiles"
  mkdir -p "$state"
  "$HOME/.local/bin/dotfiles-fingerprint" > "$state/built"
fi
#+end_src

=dotfiles-status= prints one line of JSON for Waybar's =custom/dotfiles=
module (see [[*Bar: nix/desktop/waybar.nix][Bar]]). Empty text hides the module.

#+begin_src sh :tangle live/bin/dotfiles-status :tangle-mode o755
#!/usr/bin/env bash
# GENERATED from config.org ("Foundations / Rebuild status"). Do not edit; edit config.org.
# dotfiles-status: one line of JSON for Waybar: "rebuild" when the Nix files
# differ from the running system, and a note when a new NixOS release is out.
state="${XDG_STATE_HOME:-$HOME/.local/state}/dotfiles"
text=""
tooltip=""
class=""
if [ "$("$HOME/.local/bin/dotfiles-fingerprint" 2>/dev/null)" != "$(cat "$state/built" 2>/dev/null)" ]; then
  text="rebuild"
  tooltip="The Nix files changed since the last rebuild. Click to rebuild."
  class="rebuild"
fi
if [ -r /var/lib/dotfiles-update/new-release ]; then
  release=$(cat /var/lib/dotfiles-update/new-release)
  text="${text:+$text · }NixOS $release"
  tooltip="${tooltip:+$tooltip\\n}NixOS $release is out: see Moving to the next release in config.org."
  class="${class:-release}"
fi
printf '{"text": "%s", "tooltip": "%s", "class": "%s"}\n' "$text" "$tooltip" "$class"
#+end_src

** Weekly updates: nix/core/updates.nix
:PROPERTIES:
:header-args:nix: :tangle nix/core/updates.nix
:END:

Once a week (Monday around noon, or at the next start if the machine was
off) a system service:

1. updates =flake.lock= to the newest versions of every input, *as you*, so
   the file stays yours;
2. builds the new system, as you; if that fails, it puts the old
   =flake.lock= back and stops;
3. makes the new system the default *for the next boot* (it never changes
   the running system under your hands);
4. commits =flake.lock= (only that file);
5. checks whether the next NixOS release exists, and if so leaves a note
   that the bar shows.

You never have to remember to update, and an update never lands in the
middle of a lesson: it arrives at the next boot, and the previous version
stays in the boot menu. =sudo systemctl start dotfiles-update= runs it now;
=journalctl -u dotfiles-update= shows what it did. A failure shows up in
the bar (=systemd-failed-units=).

The service builds what is in =~/dotfiles= at that moment, including
uncommitted changes, just like =rebuild=.

#+begin_src nix
# GENERATED from config.org ("Foundations / Weekly updates"). Do not edit; edit config.org.
# nix/core/updates.nix: the weekly update of flake.lock and of the system
# for the next boot, and the reminder for a new NixOS release.
{
  config,
  lib,
  pkgs,
  username,
  hostName,
  ...
}:

let
  update = pkgs.writeShellApplication {
    name = "dotfiles-update";
    runtimeInputs = [
      pkgs.coreutils
      pkgs.git
      pkgs.util-linux # runuser
      config.nix.package
    ];
    text = ''
      user=${lib.escapeShellArg username}
      home=${lib.escapeShellArg config.users.users.${username}.home}
      repo=${lib.escapeShellArg "${config.users.users.${username}.home}/dotfiles"}
      host=${lib.escapeShellArg hostName}
      release=${lib.escapeShellArg "<<release>>"}
    ''
    + builtins.readFile ./dotfiles-update.sh;
  };
in
{
  systemd.services.dotfiles-update = {
    description = "Weekly update of flake.lock and of the system for the next boot";
    wants = [ "network-online.target" ];
    after = [ "network-online.target" ];
    restartIfChanged = false; # never run as a side effect of a rebuild
    startAt = "Mon *-*-* 12:00:00";
    serviceConfig = {
      Type = "oneshot";
      ExecStart = lib.getExe update;
      StateDirectory = "dotfiles-update"; # /var/lib/dotfiles-update
    };
  };

  systemd.timers.dotfiles-update.timerConfig = {
    Persistent = true; # catch up after a week with the machine off
    RandomizedDelaySec = "30min";
  };

  environment.systemPackages = [ update ];
}
#+end_src

*** The job: nix/core/dotfiles-update.sh

The Nix block above puts =user=, =home=, =repo=, =host= and =release= in front of
this text. The commands that touch your repository run as you
(=runuser=); only making the new system the boot default needs root.

#+begin_src sh :tangle nix/core/dotfiles-update.sh
# GENERATED from config.org ("Foundations / Weekly updates"). Do not edit; edit config.org.
# dotfiles-update: run weekly by systemd, as root. Nix defines $user, $repo,
# $home, $host and $release before this text.
# As you, with your own home folder (for git's settings and Nix's cache).
as_user() { runuser -u "$user" -- env HOME="$home" "$@"; }

# 1. Newer versions of every input.
as_user nix flake update --flake "$repo"

if as_user git -C "$repo" diff --quiet -- flake.lock; then
  echo "dotfiles-update: everything was already up to date"
else
  # 2. Build the new system as you; on failure keep the old flake.lock.
  if ! system=$(as_user nix build --no-link --print-out-paths \
    "$repo#nixosConfigurations.$host.config.system.build.toplevel"); then
    as_user git -C "$repo" checkout -- flake.lock
    echo "dotfiles-update: the build failed; flake.lock is unchanged" >&2
    exit 1
  fi
  # 3. The default for the next boot (what `nixos-rebuild boot` does).
  nix-env --profile /nix/var/nix/profiles/system --set "$system"
  "$system/bin/switch-to-configuration" boot
  # 4. Keep the new flake.lock, and nothing else, in git.
  as_user git -C "$repo" commit --quiet -m "flake.lock: weekly update" -- flake.lock
  echo "dotfiles-update: the new system starts at the next boot"
fi

# 5. Is the next NixOS release out? (YY.05 is followed by YY.11, YY.11 by YY+1.05.)
year=${release%.*}
month=${release#*.}
if [ "$month" = 05 ]; then
  next="$year.11"
else
  next="$((10#$year + 1)).05"
fi
if git ls-remote --exit-code --heads https://github.com/NixOS/nixpkgs "nixos-$next" > /dev/null 2>&1; then
  echo "$next" > /var/lib/dotfiles-update/new-release
else
  rm -f /var/lib/dotfiles-update/new-release
fi
#+end_src

*** Moving to the next release

Twice a year NixOS publishes a release (=YY.05= and =YY.11=); each is
supported for seven months, so 26.05 until 31 December 2026. When the bar
says "NixOS 26.11", within a few weeks:

1. Read the release notes' section /Backward incompatibilities/
   (nixos.org/manual/nixos/stable/release-notes).
2. Change [[*The NixOS release][The NixOS release]] to the new value and save. That is the only
   place the release is written.
3. =rebuild build= (build only). Fix what the messages report: usually a
   renamed option, and the message names the new one.
4. =rebuild boot=, reboot, and commit.
5. Never change =system.stateVersion= in the machine sections: it records
   the release a machine was /installed/ with.

*** Switching to unstable instead

If you would rather follow =nixos-unstable= (newest versions, no release
jumps), these are the changes, all in this file:

1. In [[*Inputs][Inputs]]: =nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";=, and
   remove the =nixpkgs-unstable= input; =emacs-overlay= then follows
   =nixpkgs= only.
2. In [[*Nix itself: nix/core/nix.nix][Nix itself]]: remove the =unstable= overlay.
3. Remove the =unstable.= prefixes (=pkgs.unstable.emacs-pgtk= becomes
   =pkgs.emacs-pgtk=, the =dev-tools= pieces likewise).
4. In the update job, remove step 5; the release block becomes unused.

The weekly job then brings everything up to date each week, still for the
next boot, with the previous version in the boot menu.

:PROPERTIES:

NixOS on the USB SSD stick, booted on the EliteBook. It leaves the laptop's

#+begin_src nix
# GENERATED from config.org ("Machines / nixusb"). Do not edit; edit config.org.
# nix/hosts/nixusb/default.nix: the USB test installation.
{ hostName, ... }:

{
  imports = [
    ./hardware-configuration.nix # written by the installer; copy it in
  ];

  networking.hostName = hostName; # "nixusb", from flake.nix

  # Boot loader on a USB disk: do NOT write boot entries into the laptop's
  # firmware (that is where Windows's entry lives). systemd-boot still
  # installs itself as the removable-media fallback (EFI/BOOT/BOOTX64.EFI),
  # so the stick boots from the firmware's one-time boot menu (Esc, F9 on HP).
  boot.loader.efi.canTouchEfiVariables = false;

  # Make sure the USB disk can be found early in boot on any machine.
  boot.initrd.availableKernelModules = [
    "xhci_pci"
    "usb_storage"
    "uas"
    "sd_mod"
  ];

  # Fewer writes to the USB disk: don't record when files were last read.
  fileSystems."/".options = [ "noatime" ];

  # The EliteBook's built-in keyboard is broken: its left Ctrl key now and
  # then sends a press without a release, so Linux thinks Ctrl is held down
  # (on text screens m then acts as Enter and i as Tab). Ignore that one
  # key of the built-in keyboard (scancode 1d, found with evtest). atkbd
  # matches only built-in keyboards, never the external USB one. The
  # KEYBOARD_KEY line needs exactly one space more than the evdev line;
  # Nix removes the common indentation of the '' string.
  services.udev.extraHwdb = ''
    evdev:atkbd:dmi:*
     KEYBOARD_KEY_1d=reserved
  '';

  # No games here: the EliteBook's fan is broken and Civilization IV makes
  # it overheat. They are switched on for the laptop.

  # The release this machine was installed with. Never change it.
  system.stateVersion = "26.05";
}

*** Window helpers: run-or-raise and power-menu

=run-or-raise APP-ID COMMAND...= focuses the window of that app if one is
open and runs the command otherwise (=Mod+B=, =Mod+M=, =Mod+Shift+W=).
=power-menu= offers lock, suspend, log out, reboot and power off in fuzzel
(=Mod+X=). Both are linked into =~/.local/bin=.

#+begin_src sh :tangle live/bin/run-or-raise :tangle-mode o755
#!/usr/bin/env bash
# GENERATED from config.org ("Desktop / niri"). Do not edit; edit config.org.
# run-or-raise APP-ID COMMAND...: focus the window of that app if one is
# open, otherwise start the command. Used by niri's Mod+B, Mod+M, Mod+Shift+W.
set -euo pipefail
app="$1"
shift
id=$(niri msg --json windows |
  jq -r --arg app "$app" 'first(.[] | select(.app_id == $app) | .id) // empty')
if [ -n "$id" ]; then
  niri msg action focus-window --id "$id"
else
  exec "$@"
fi
#+end_src

#+begin_src sh :tangle live/bin/power-menu :tangle-mode o755
#!/usr/bin/env bash
# GENERATED from config.org ("Desktop / niri"). Do not edit; edit config.org.
# power-menu: lock, suspend, log out, reboot or shut down, chosen in fuzzel.
set -euo pipefail
choice=$(printf '%s\n' lock suspend logout reboot poweroff |
  fuzzel --dmenu --prompt "power: " --lines 5 --width 20) || exit 0
case "$choice" in
  lock) loginctl lock-session ;;
  suspend) systemctl suspend ;;
  logout) niri msg action quit --skip-confirmation ;;
  reboot) systemctl reboot ;;
  poweroff) systemctl poweroff ;;
esac
#+end_src

** Mathematical notation: one source for LaTeX and slides

The same macros in handouts and on slides: =\R=, =\abs*{x}=, =\argmax_x=
mean the same thing in a LaTeX document and in a reveal.js deck. They are
written *once*, in the blocks below, which are not written to any file by
themselves. Two files take them in:

- =MJPreamble.sty= (see [[*Notation][Notation]] in the preamble), for LaTeX;
- =live/slides/mj-notation.js=, for reveal.js decks, which typeset maths with
  MathJax.

MathJax (3.2.1 or later, and MathJax 4) understands this part of LaTeX: =\newcommand=,
=\DeclareMathOperator= and, with its mathtools extension, the self-sizing
brackets of =\DeclarePairedDelimiter=, including the starred and sized forms.

*Older decks.* Decks made before this notation define their own MathJax
macros, among them a two-argument =\set= with a semicolon
(=\set{x \in \R}{x > 0}=). Such a deck keeps working as it is, because it
does not load =mj-notation.js=. When you move a deck over to the shared
notation, rewrite those sets as =\set{x \in \R \given x > 0}=: the old form
would show ={x ∈ ℝ}x > 0= without any error. =rg '\\set\{[^}]*\}\{' -g '*.html'=
in a course folder lists the places (it finds most of them; a set with
braces inside its first part needs a look by eye).

Three macros cannot be written the same way for both, so they have two
definitions with the same name and the same use:

- =\set= with =\given=: in LaTeX the bar inside =\set*{x \given x > 0}= grows
  with the braces, because the definition redefines =\given= for the
  duration of the braces. MathJax has no such "for the duration": a
  redefinition would last for the whole page. On slides the bar keeps its
  normal size.
- =\ubar= uses the accents package, which MathJax lacks; slides underline
  instead.
- =\mathbbm= (dsfont's double-struck letters in LaTeX) becomes =\mathbb= on
  slides.

And three exist only on slides: =\Lint=, =\LLint=, =\Hint=, the larger
integral signs from your decks (LaTeX does not allow text sizes in maths).

*** The file for reveal.js: live/slides/mj-notation.js

A deck uses it in two lines: load the file, and let it fill in the MathJax
options of reveal.js's math plugin. =MJNotation.mathjax3()= returns those
options: it adds the mathtools extension and runs the definitions once,
before the first equation is typeset, one definition at a time (so that a
definition one MathJax version handles differently cannot stop the
others). Your own MathJax options can be passed in, for example a local
copy of MathJax: =MJNotation.mathjax3({ mathjax: "mathjax/tex-mml-chtml.js" })=.
With MathJax 4 (recent reveal.js, such as 6.0) write =mathjax4: MJNotation.mathjax4()=
and =RevealMath.MathJax4= instead; the options are the same.

#+begin_src js :tangle live/slides/mj-notation.js
// GENERATED from config.org ("Writing and teaching / Mathematical notation"). Do not edit; edit config.org.
// mj-notation.js: the notation of MJPreamble.sty for reveal.js decks that
// typeset maths with MathJax 3.2.1 or later, or MathJax 4.
//
//   <script src="mj-notation.js"></script>
//   Reveal.initialize({ mathjax3: MJNotation.mathjax3(), plugins: [RevealMath.MathJax3] });
// or, with MathJax 4 (recent reveal.js, such as 6.0):
//   Reveal.initialize({ mathjax4: MJNotation.mathjax4(), plugins: [RevealMath.MathJax4] });
(function () {
  "use strict";

  // The definitions shared with MJPreamble.sty, then the slides' own.
  const definitions = String.raw`
<<maths-notation>>
<<maths-notation-slides>>
`;

  // MathJax options for the math plugin: load mathtools (for the self-sizing
  // brackets) and run the definitions once, before the page is typeset.
  // OPTIONS are your own MathJax options; they are kept.
  function mathjax3(options) {
    const config = Object.assign({}, options);

    const loader = Object.assign({}, config.loader);
    loader.load = (loader.load || []).concat(["[tex]/mathtools"]);
    config.loader = loader;

    const tex = Object.assign({}, config.tex);
    if (Array.isArray(tex.packages)) {
      tex.packages = tex.packages.concat(["mathtools"]);
    } else {
      const packages = Object.assign({}, tex.packages);
      packages["[+]"] = (packages["[+]"] || []).concat(["mathtools"]);
      tex.packages = packages;
    }
    config.tex = tex;

    const startup = Object.assign({}, config.startup);
    const ownPageReady = startup.pageReady;
    startup.pageReady = function () {
      const MathJax = window.MathJax;
      // One definition at a time, so that one MathJax rejects (or one that
      // needs an extension loaded first) cannot take the others with it.
      const lines = definitions
        .split("\n")
        .filter((line) => line.trim() !== "" && !line.trim().startsWith("%"));
      let done = Promise.resolve();
      for (const line of lines) {
        done = done.then(() =>
          MathJax.tex2mmlPromise(line).catch((error) =>
            console.warn("mj-notation: could not define", line, error),
          ),
        );
      }
      return done.then(() => (ownPageReady ? ownPageReady() : MathJax.startup.defaultPageReady()));
    };
    config.startup = startup;

    return config;
  }

  window.MJNotation = { definitions: definitions, mathjax3: mathjax3, mathjax4: mathjax3 };
})();
#+end_src

**** Language, fonts and micro-typography

Both languages are always loaded, so a document can switch for a passage
(=\foreignlanguage{dutch}{...}=); the option only decides which one is
the main language. cleveref does not ask babel which language is used, so
it is told directly.

The T1 font encoding makes words with accents hyphenate correctly and
copy out of the PDF as one word. inputenc is no longer needed: UTF-8 has
been LaTeX's default input encoding since 2018.

microtype improves spacing and justification in small ways: fewer
hyphenated lines, more even word spacing. It needs scalable fonts, which
cm-super provides (see the TeX Live list).

setspace is loaded here, before microtype, but switched on at the end
(see [[*Line spacing][Line spacing]]). setspace changes how footnotes are set; loaded
after microtype, it undoes microtype's adjustment of footnotes, and
microtype warns about it.

#+begin_src latex
\ifMJ@dutch
  \RequirePackage[english,main=dutch]{babel}
  \PassOptionsToPackage{dutch}{cleveref}
\else
  \RequirePackage[dutch,main=english]{babel}
\fi
\RequirePackage[T1]{fontenc}
\RequirePackage{setspace}
\RequirePackage{microtype}
#+end_src

**** Mathematics

mathtools extends amsmath and loads it, so amsmath is not loaded
separately. amsthm must come /after/ amsmath: it checks at load time
whether amsmath is present, and if not, takes a fallback route in which
=\qedhere= inside a displayed equation is unreliable.

- amssymb: the AMS symbols, and =\mathbb=.
- dsfont: =\mathds=, e.g. =\mathds{1}= for indicator functions. It
  replaces bbm, whose fonts exist only as bitmaps, which look blurry when
  zoomed in or projected. dsfont covers the capitals, 1, h and k.
  =\mathbbm= still works (see [[*Notation][Notation]]), so older documents compile.
- bm: bold maths symbols, =\bm{x}=. It comes before stmaryrd, which has
  no bold version; the other order gives a font warning.
- stmaryrd: extra symbols such as =\llbracket= and =\rrbracket=.
- accents: =\underaccent=, used by =\ubar= below.

#+begin_src latex
\RequirePackage{mathtools}
\RequirePackage{amssymb}
\RequirePackage{amsthm}
\RequirePackage{dsfont}
\RequirePackage{bm}
\RequirePackage{stmaryrd}
\RequirePackage{accents}
#+end_src

**** Colour, tables and pictures

packages: it loads colortbl itself, which brings =\rowcolor=,

before TikZ, which also loads xcolor; the other order would give an
option clash.

**** Theorems

*One counter for all kinds*: Theorem 1, Lemma 2, Definition 3. A reader
looking for "Lemma 2" then knows it comes after Theorem 1. In a document
with sections, the numbers start again in each section and carry the
section's number (Theorem 2.1, Lemma 2.2); in a handout without sections
they stay plain (Theorem 1), instead of the "Theorem 0.1" that ordinary
numbering by section would give.

*Styles*: theorem, proposition, lemma, sublemma and corollary in the
/plain/ style (italic text); definition and example in the /definition/
style (upright text); remark in the /remark/ style. Proofs use amsthm's
=proof= environment.

#+begin_src latex
\newtheorem{theorem}{\MJ@name{Theorem}{Stelling}}
\counterwithin*{theorem}{section}
\renewcommand{\thetheorem}{\ifnum\value{section}>0 \thesection.\fi\arabic{theorem}}
\newtheorem{proposition}[theorem]{\MJ@name{Proposition}{Propositie}}
\newtheorem{lemma}[theorem]{Lemma}
\newtheorem{sublemma}[theorem]{Sublemma}
\newtheorem{corollary}[theorem]{\MJ@name{Corollary}{Gevolg}}
\theoremstyle{definition}
\newtheorem{definition}[theorem]{\MJ@name{Definition}{Definitie}}
\newtheorem{example}[theorem]{\MJ@name{Example}{Voorbeeld}}
\theoremstyle{remark}
\newtheorem{remark}[theorem]{\MJ@name{Remark}{Opmerking}}
#+end_src

*Checksums.* When a checksum below is empty, the launcher prints the
checksum of the file it found; paste it here to pin that exact file. From
then on a different file is refused.

are not configuration: they are created on the first start and stay. To
reinstall a game, delete its folder (named below) and start it again.

USB stick, because the EliteBook overheats.

#+begin_src nix
# GENERATED from config.org ("Games"). Do not edit; edit config.org.
# nix/desktop/games.nix: Caesar III (Augustus) and Civilization IV with BUG,
# installed by their launchers from the files in ~/Games/installers.
{
  config,
  lib,
  pkgs,
  username,
  ...
}:

let
  cfg = config.games;
  installers = "/home/${username}/Games/installers";

  # A launcher: shell variables from SETTINGS, the shared functions, the script.
  launcher =
    name: script: settings: runtimeInputs:
    pkgs.writeShellApplication {
      inherit name runtinmeInputs;
      text =
        lib.concatStrings (lib.mapAttrsToList (k: v: "${k}=${lib.escapeShellArg v}\n") settings)
        + builtins.readFile ./games/common.sh
        + builtins.readFile script;
    };

  entry =
    name: desktopName:
    pkgs.makeDesktopItem {
      inherit name desktopName;
      exec = name;
      icon = "applications-games";
      categories = [ "Game" ];
    };

  caesar3 = launcher "caesar3" ./games/caesar3.sh {
    inherit installers;
    installer = cfg.caesar3.installer;
    sha256 = cfg.caesar3.sha256;
  } (with pkgs; [ augustus innoextract coreutils findutils ]);

  civ4 = launcher "civ4" ./games/civ4.sh {
    inherit installers;
    installer = cfg.civ4.installer;
    sha256 = cfg.civ4.sha256;
    bug = cfg.civ4.bug;
    bug_sha256 = cfg.civ4.bugSha256;
  } (with pkgs; [ winePackages.stable winetricks coreutils findutils unzip cabextract ]);
in
{
  options.games = {
    caesar3 = {
      enable = lib.mkEnableOption "Caesar III, played through Augustus";
      installer = lib.mkOption {
        type = lib.types.str;
        default = "setup_caesar*.exe";
        description = "Name pattern of GOG's offline installer in ~/Games/installers.";
      };
      sha256 = lib.mkOption {
        type = lib.types.str;
        default = "";
        description = "Its SHA-256 checksum; empty: not checked (the launcher prints it).";

#+begin_src sh :tangle nix/desktop/games/common.sh
# GENERATED from config.org ("Games"). Do not edit; edit config.org.
# Shared by the game launchers. $installers is set by Nix before this text.

# find_one PATTERN WHAT: the single file in $installers matching PATTERN.
find_one() {
  local matches
  shopt -s nullglob
  # shellcheck disable=SC2206 # the pattern must expand here
  matches=("$installers"/$1)
  shopt -u nullglob
  if [ "${#matches[@]}" -ne 1 ]; then
    echo "Expected one file matching '$1' in $installers, found ${#matches[@]}." >&2
    echo "Put $2 there (see Games in config.org), then start the game again." >&2
    exit 1
  fi
  printf '%s\n' "${matches[0]}"
}

# check_sum FILE EXPECTED: compare FILE with the checksum from config.org.
check_sum() {
  local actual
  actual=$(sha256sum "$1" | cut -d' ' -f1)
  if [ -z "$2" ]; then
    echo "Checksum of $(basename "$1"): $actual"
    echo "(put it in config.org, Games, to pin exactly this file)"
  elif [ "$actual" != "$2" ]; then
    echo "$(basename "$1") does not match its checksum in config.org; stopping." >&2
    exit 1
  fi
}
#+end_src

** Caesar III: nix/desktop/games/caesar3.sh

Augustus is a modern engine for Caesar III's original files, with fixes and
extras (larger screens, better interface). On the first start, =caesar3=
unpacks the game files from GOG's installer with innoextract (no Wine
involved) into =~/.local/share/caesar3=, the folder that holds =c3.eng=.
Augustus runs from there and keeps your saved games in it: that folder is
the game's state. Copy saved games (=*.sav=) from your Windows installation
into it.

#+begin_src sh :tangle nix/desktop/games/caesar3.sh
# GENERATED from config.org ("Games / Caesar III"). Do not edit; edit config.org.
# caesar3: Caesar III through Augustus. The first start unpacks the game
# files from GOG's installer into ~/.local/share/caesar3, where Augustus
# also keeps your saved games.

  fi
  mkdir -p "$data"
  cp -R --no-preserve=mode "$(dirname "$marker")"/. "$data"/
  rm -rf "$tmp"
  touch "$data/.installed"
fi

exec augustus "$data"

** Civilization IV with BUG: nix/desktop/games/civ4.sh

Civilization IV is a 32-bit Windows game and runs under Wine, in a Wine
folder ("prefix") of its own: =~/.local/share/wine/civ4=. What makes it work
well, from players' experience: a 32-bit prefix (with Nix's 32-bit Wine,
=winePackages=; the newer "wow64" Wine cannot make one), Microsoft's =msxml3= (the
game crashes at certain moments without it, e.g. when building Stonehenge)
and =d3dx9= (tile yields display correctly), and the =C= locale (the game
misreads numbers in some languages). The first start does all of this, with
=winetricks sandbox= first, so the prefix's "Documents" is a folder of its
own instead of a link to yours. Then GOG's installer runs silently.

*BUG* goes into =My Games\Beyond the Sword= inside the prefix (its
=CustomAssets= folder, so it is active in every game). The launcher only
installs it when that folder is missing, so your own copy wins: if you move
your Windows =Documents\My Games\Beyond the Sword= folder into the prefix
(saved games, BUG and its settings), nothing is overwritten. Press
=Alt+Ctrl+O= in the game for BUG's options.

The first start needs the internet (for msxml3 and d3dx9) and takes a few
minutes.

#+begin_src sh :tangle nix/desktop/games/civ4.sh
# GENERATED from config.org ("Games / Civilization IV with BUG"). Do not edit; edit config.org.
# civ4: Civilization IV (Beyond the Sword) under Wine, with the BUG mod.
# The first start creates a 32-bit Wine prefix, adds msxml3 and d3dx9 and
# runs GOG's installer; BUG is installed whenever it is missing.
export WINEPREFIX="${XDG_DATA_HOME:-$HOME/.local/share}/wine/civ4"
export WINEARCH=win32
export WINEDEBUG=-all
export LC_ALL=C
game_windows='C:\GOG Games\Civilization IV Complete'
game="$WINEPREFIX/drive_c/GOG Games/Civilization IV Complete"

if [ ! -e "$WINEPREFIX/.installed" ]; then
  setup=$(find_one "$installer" "GOG's offline installer for Civilization IV (all its files)")
  check_sum "$setup" "$sha256"
  echo "Creating the Wine prefix, with msxml3 and d3dx9 (needs the internet) ..."
  mkdir -p "$(dirname "$WINEPREFIX")"
  wineboot --init
  winetricks -q sandbox msxml3 d3dx9
  echo "Running GOG's installer ..."
  wine "$setup" /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /DIR="$game_windows"
  wineserver --wait
  touch "$WINEPREFIX/.installed"
fi

my_games="$WINEPREFIX/drive_c/users/$USER/Documents/My Games/Beyond the Sword"
if [ ! -d "$my_games/CustomAssets" ]; then
  zip=$(find_one "$bug" "the BUG mod's zip from civ4bug.sourceforge.net")
  check_sum "$zip" "$bug_sha256"
  tmp=$(mktemp -d)
  unzip -q "$zip" -d "$tmp"
  # The zip may hold CustomAssets at the top or inside a folder of its own:
  # what goes into "Beyond the Sword" is the folder that contains it.
  assets=$(find "$tmp" -type d -iname 'CustomAssets' -print -quit)
  if [ -z "$assets" ]; then
    rm -rf "$tmp"
    echo "No CustomAssets folder found in $(basename "$zip"); is it the BUG mod?" >&2
    exit 1
  fi
  mkdir -p "$my_games"
  cp -R --no-preserve=mode "$(dirname "$assets")"/. "$my_games"/
  rm -rf "$tmp"
  echo "BUG installed in My Games/Beyond the Sword."
fi

cd "$game/Beyond the Sword"
exec wine Civ4BeyondSword.exe "$@"
#+end_src

** Tangling, cleaning up and staging: live/emacs/dotfiles-tangle.el

What happens when =config.org= is saved, in a file of its own so the
=tangle-config= command can run it without the rest of the configuration
(=emacs --batch=). It works on NixOS and on Windows.

1. *Tangle* the whole file, with Unix line endings (so the files are the
   same on both machines) and blocks exactly as written. Org reports which
   files it wrote.
2. *Clean up.* The list of files written is kept on this machine
   (=~/.emacs.d/dotfiles-tangled.eld=). A file that was on the previous list
   but not on this one belongs to a section that was removed or renamed;
   it is deleted, together with folders that became empty. Three safeguards:
   only files inside the repository, only files whose first lines say
   /GENERATED from config.org/ (so never =hardware-configuration.nix=,
   =flake.lock= or the README), and nothing at all when this tangle wrote
   less than half as many files as the previous one (a sign that something
   went wrong). A file deleted by mistake would anyway be written again at
   the next save.
3. *Stage* the written files, and the deletions, in git. Scripts in
   =live/bin/= are recorded as executable, also when you save on Windows,
   which has no such permission (otherwise they arrive on NixOS as ordinary
   files: /Permission denied/). Nix only sees files that git knows; staging is enough, committing stays yours. Only these
   files are staged, nothing else in the folder.
4. *Report*, in one message: how many files, what was removed, and on
   NixOS whether a rebuild is needed (the same question as =dotfiles-status=)
   and whether niri accepts its settings.

#+begin_src emacs-lisp :tangle live/emacs/dotfiles-tangle.el
;;; dotfiles-tangle.el --- GENERATED from config.org ("Emacs / Tangling"). Do not edit.  -*- lexical-binding: t; -*-

;; Saving config.org: tangle it completely, delete generated files whose
;; section disappeared, stage the generated files in git, and report.
;; Loaded by config.el, and by the `tangle-config' command (emacs --batch).

(require 'org)
(require 'ob-tangle)
(require 'seq)
(require 'subr-x)

(defconst MJ-dotfiles-dir
  (file-name-as-directory
   (expand-file-name "../.." (file-name-directory
                              (or load-file-name buffer-file-name))))
  "The dotfiles repository: two levels above live/emacs/.")

(defconst MJ-config-file (expand-file-name "config.org" MJ-dotfiles-dir)
  "The literate configuration.")

(defvar MJ-tangle-manifest (locate-user-emacs-file "dotfiles-tangled.eld")
  "File listing what the last complete tangle wrote, on this machine.")

(defconst MJ-generated-regexp "\\(?:GENERATED\\|tangled\\) from config\\.org"
  "A generated file says so in its first lines.")

(defun MJ--relative (file)
  "FILE relative to the repository."
  (file-relative-name file MJ-dotfiles-dir))

(defun MJ--generated-file-p (file)
  "Non-nil if FILE says in its first lines that it was generated."
  (with-temp-buffer
    (insert-file-contents file nil 0 1000)
    (re-search-forward MJ-generated-regexp nil t)))

(defun MJ--read-manifest ()
  "The files written by the previous complete tangle, or nil."
  (when (file-readable-p MJ-tangle-manifest)
    (with-temp-buffer
      (insert-file-contents MJ-tangle-manifest)
      (ignore-errors (read (current-buffer))))))

(defun MJ--write-manifest (files)
  "Remember FILES as written by this tangle."
  (make-directory (file-name-directory MJ-tangle-manifest) t) ; a new machine
  (with-temp-file MJ-tangle-manifest
    (prin1 files (current-buffer))))

(defun MJ--git (&rest args)
  "Run git with ARGS in the repository; return its exit status, or nil."
  (when (executable-find "git")
    (let ((default-directory MJ-dotfiles-dir))
      (apply #'call-process "git" nil (get-buffer-create " *dotfiles-git*") nil
             args))))

(defun MJ--delete-empty-parents (file)
  "Delete the folders above FILE that are now empty, up to the repository."
  (let ((dir (file-name-directory file)))
    (while (and dir
                (file-directory-p dir)
                (file-in-directory-p dir MJ-dotfiles-dir)
                (not (file-equal-p dir MJ-dotfiles-dir))
                (null (directory-files dir nil
                                       directory-files-no-dot-files-regexp t)))
      (delete-directory dir)
      (setq dir (file-name-directory (directory-file-name dir))))))

(defun MJ--rebuild-status ()
  "On NixOS: whether the Nix files differ from the running system."
  (let ((fingerprint (expand-file-name "~/.local/bin/dotfiles-fingerprint"))
        (built (expand-file-name "dotfiles/built"
                                 (or (getenv "XDG_STATE_HOME")
                                     "~/.local/state"))))
    (when (file-executable-p fingerprint)
      (let ((now (string-trim
                  (with-output-to-string
                    (call-process fingerprint nil standard-output nil))))
            (then (when (file-readable-p built)
                    (with-temp-buffer
                      (insert-file-contents built)
                      (string-trim (buffer-string))))))
        (if (equal now then)
            "nothing to rebuild"
          "Nix files changed: run rebuild")))))

(defun MJ--check-niri ()
  "On NixOS: an error message if niri rejects its generated settings."
  (let ((niri (executable-find "niri"))
        (kdl (expand-file-name "live/niri/config.kdl" MJ-dotfiles-dir)))
    (when (and niri (file-exists-p kdl))
      (with-temp-buffer
        (unless (eq 0 (call-process niri nil t nil "validate" "--config" kdl))
          (concat "niri's settings have an error: "
                  (car (last (split-string (string-trim (buffer-string))
                                           "\n")))))))))

(defun MJ-tangle-config ()
  "Tangle config.org completely, remove stale generated files, stage, report."
  (interactive)
  (let* ((default-directory MJ-dotfiles-dir)
         (coding-system-for-write 'utf-8-unix)
         (org-src-preserve-indentation t)
         (written (delete-dups
                   (mapcar #'expand-file-name
                           (let ((inhibit-message t)) ; quiet: one report at the end
                             (org-babel-tangle-file MJ-config-file)))))
         (previous (MJ--read-manifest))
         (suspicious (and previous
                          (< (length written) (/ (length previous) 2))))
         (stale (unless suspicious
                  (seq-filter (lambda (file)
                                (and (not (member file written))
                                     (file-exists-p file)
                                     (file-in-directory-p file MJ-dotfiles-dir)
                                     (MJ--generated-file-p file)))
                              previous)))
         (parts (list (format "Tangled %d files" (length written)))))
    (dolist (file stale)
      (delete-file file)
      (MJ--delete-empty-parents file))
    (unless suspicious
      (MJ--write-manifest written))
    ;; Stage the written files and the deletions, so Nix sees them.
    (when written
      (apply #'MJ--git "add" "--" (mapcar #'MJ--relative written)))
    ;; Scripts in live/bin must be executable on NixOS. Windows has no such
    ;; permission, and git there would record them as ordinary files; so set
    ;; the bit in git itself (harmless on NixOS, where it is set already).
    (let ((scripts (seq-filter (lambda (f) (string-prefix-p "live/bin/" f))
                               (mapcar #'MJ--relative written))))
      (when scripts
        (apply #'MJ--git "update-index" "--chmod=+x" "--" scripts)))
    (when stale
      (apply #'MJ--git "rm" "--cached" "--quiet" "--ignore-unmatch" "--"
             (mapcar #'MJ--relative stale)))
    (when stale
      (push (format "removed %s" (mapconcat #'MJ--relative stale ", ")) parts))
    (when suspicious
      (push "far fewer files than last time, so nothing was removed" parts))
    (let ((status (MJ--rebuild-status)))
      (when status (push status parts)))
    (let ((niri (MJ--check-niri)))
      (when niri (push niri parts)))
    (let ((report (mapconcat #'identity (nreverse parts) "; ")))
      (message "%s" report)
      report)))

(defun MJ-date-config ()
  "Before config.org is saved: set its #+DATE line to today's date."
  (when (and buffer-file-name
             (file-equal-p buffer-file-name MJ-config-file))
    (save-excursion
      (goto-char (point-min))
      ;; Only the header (the first 20 lines), never a #+DATE further down.
      (when (re-search-forward "^#\\+DATE: .*$"
                               (save-excursion (forward-line 20) (point)) t)
        (let ((today (format-time-string "#+DATE: %Y-%m-%d")))
          (unless (equal (match-string 0) today)
            (replace-match today t t)))))))

(defun MJ-tangle-batch ()
  "Entry point for `emacs --batch': see `MJ-tangle-config'."
  (MJ-tangle-config))

#+end_src

** Language servers (eglot)

eglot is built in and replaces lsp-mode, lsp-pyright and lsp-latex. A
helper starts eglot only when the server is actually on =PATH=, so a
machine without a given server simply skips it.

The lsp-mode indentation workaround (issue #2915, the =lsp--get-indent-width=
advice and the =tab-width= hook) is gone: eglot never drives indentation,
so web-mode's own offsets always apply.

*File watching on Windows.* Language servers can ask the editor to watch
folders for changes. basedpyright asks to watch the project /and the whole
Python installation/; on Windows eglot cannot set up that many watches,
replies with an error, and basedpyright crashes on that error ("Not
auto-reconnecting, last one didn't last long"). On Windows, eglot therefore
accepts such requests without watching. Cost: files created or renamed
outside Emacs are noticed after reopening the file or =M-x
eglot-reconnect=.

*JavaScript and TypeScript.* TypeScript 7 (July 2026) is a native rewrite
with its own language server, started as =tsc --lsp --stdio=; it no longer
ships the =tsserver.js= that the separate typescript-language-server
needs. =MJ-js-server= asks =tsc --version= when a JavaScript file is
opened and picks =tsc --lsp= for version 7 or later, and
typescript-language-server for older versions (for example an older
package set on NixOS). Installing =typescript= (=npm install -g
typescript=) is enough on Windows.

*Unsupported optional features.* Some servers offer features eglot does
not support, and eglot warns about each ("Server tried to register
unsupported capability ..."). Two such offers are accepted silently: the
HTML server's =workspace/didChangeWorkspaceFolders= (tracking several
project folders; one is all I need) and TypeScript 7's
=workspace/didChangeConfiguration= (eglot sends its settings at startup
anyway).

*Mode-line indicator.* eglot's indicator uses a green that is unreadable
with deeper-blue; it now uses the mode line's own emphasis style.

*Type-checking level.* basedpyright's default mode is strict: it warns
about every missing type annotation, which is noise for beginners' code
and teaching material. "standard" matches plain pyright. Switch per project
with a =[tool.basedpyright]= section in =pyproject.toml= if wanted.

#+begin_src emacs-lisp
(defun MJ-eglot-ensure-if (program)
  "Return a hook function that starts eglot only if PROGRAM is on PATH."
  (lambda ()
    (when (executable-find program)
      (eglot-ensure))))

             (string-match "Version \\([0-9]+\\)" version)
             (>= (string-to-number (match-string 1 version)) 7))
        '("tsc" "--lsp" "--stdio")
      '("typescript-language-server" "--stdio"))))

** Snippets

yasnippet expands an abbreviation into a template (=TAB=); eglot also uses
it for completions with placeholders. The community collection
(yasnippet-snippets) comes as a package. *Your own snippets* are written
from this section into =live/emacs/snippets/<mode>/<name>=, and yasnippet
looks there instead of in =~/.emacs.d/snippets/=. That folder is in the
repository, so the snippets are the same at home, at work and on NixOS
(snippets made with =M-x yas-new-snippet= and saved in =~/.emacs.d= stay on
one machine: that is why yours did not travel). To keep one: copy its text
into a block below, with the GENERATED line, and save.

*Backslashes.* In a snippet, =\= is an escape character: =\(= expands to
=(= and =\\= to one =\=. So every backslash you want in the result is
written twice: =\\documentclass= for =\documentclass=, and four backslashes
for the two a JavaScript string needs (="\\\\("= gives ="\\("=). Org copies
the blocks exactly as written, so this rule is the only one to remember.
Test a snippet with =C-c C-t= in its file (=M-x yas-visit-snippet-file=):
that expands it in a scratch buffer.

** Formatting (Apheleia)

Apheleia formats buffers on save: ruff for Python (replacing black: same
style, much faster), Prettier for HTML/CSS/JS. It replaced blacken and
prettier-js; prettier-js never worked reliably on Windows here, for reasons
that weren't pinned down.

*How it works.* Apheleia sends the buffer's contents to the formatter in
the background, then runs the external =diff= program to compare the
original and formatted text, and applies only the changes. This keeps
point, marks and undo history intact, and skips the update if you edited
the buffer in the meantime.

*External requirements* (all on =exec-path=):
- =diff= (on Windows: Scoop's diffutils or Git's =usr/bin=);
- =bash= on Windows, because Apheleia runs Prettier through a bundled bash
  script, "apheleia-npx" (Git for Windows' bash works);
- Prettier (=npm install -g prettier=) and ruff (=uv tool install ruff=;
  on NixOS a =dev-tools= piece).

*Troubleshooting.* Apheleia fails silently. If saving doesn't format, run
=M-x apheleia-goto-error= right after saving to see the formatter's output.
Prettier honours =.prettierignore= files in the project and its parent
folders; a project-level one (e.g. reveal.js's own, which excludes all
=*.html=) makes Prettier report success while changing nothing. Check with
=prettier --file-info <file>=.

*Removing a list item.* Org renumbers a list when items are moved
(=M-<up>=, =M-<down>=) but not when one is killed; that needed a =C-c
C-c= afterwards. =C-c k= kills the item the cursor is in (anywhere on any
of its lines, sub-items included) and renumbers the list, fixing
checkbox counters like =[1/3]= too. =C-u C-c k= deletes it without
saving it to the kill ring. The kill ring gets the item without its
bullet, so =M-RET= then =C-y= elsewhere moves it with a correct bullet.
It uses Org's own list functions, the ones behind =M-<up>= and
=M-<down>=; Org has no built-in command for this (checked up to 9.8).

#+begin_src emacs-lisp
(defun MJ-org-kill-list-item (&optional delete)
  "Kill the list item at point, sub-items included, and renumber the list.
With a prefix argument, DELETE the item instead of saving it to the kill ring."
  (interactive "P")
  (let ((item (or (org-in-item-p) (user-error "Not in a list item"))))
    (goto-char item)
    (let ((struct (org-list-send-item item (if delete 'delete 'kill)
                                      (org-list-struct))))
      (org-list-write-struct struct (org-list-parents-alist struct))
      (org-update-checkbox-count-maybe))))

(with-eval-after-load 'org
  (define-key org-mode-map (kbd "C-c k") #'MJ-org-kill-list-item))
#+end_src

** Customize settings (loaded last)

One exception needs care: =custom.el= also stores

=use-package= installs a new package during startup, it adds it to that

        (delete-dups (append installed-this-session package-selected-packages))))

** Torrents: nix/server/qbittorrent.nix
:PROPERTIES:
:header-args:nix: :tangle nix/server/qbittorrent.nix
:END:

qBittorrent without a window (=qbittorrent-nox=), as a system service that
starts at boot, controlled from the laptop's browser at
=http://server.local:8080=. It runs as your own account, so the files it
downloads to the WD drive are yours and the torrent list moved from Windows
keeps working without changing owners.

The WD drive stays NTFS, so Windows can still read it. =ntfs3= is the
kernel's own NTFS driver; =nofail= lets the server boot when the drive is
unplugged, and qBittorrent waits for the drive (=RequiresMountsFor=)
rather than filling the empty folder underneath it.

The drive is found by its label. Look it up once with =lsblk -f= and put it
in =device= (or use =/dev/disk/by-uuid/...=).

*Settings* such as the download folder, speed limits and the web password
are chosen in the web interface and kept in qBittorrent's own files
(state, see [[*State: what is not in this file][State]]). On first start
qBittorrent prints a temporary web password in its log:
=journalctl -u qbittorrent=.

#+begin_src nix
# GENERATED from config.org ("Home server / Torrents"). Do not edit; edit config.org.
# nix/server/qbittorrent.nix: qBittorrent as a service, with the WD drive.
{ username, ... }:

{
  services.qbittorrent = {
    enable = true;
    user = username; # downloads belong to you
    group = "users";
    webuiPort = 8080; # http://server.local:8080
    torrentingPort = 51413; # the port other peers connect to
    openFirewall = true; # opens both ports
  };

  # The WD drive, NTFS, at /srv/torrents. Change the label to the drive's
  # own (lsblk -f).
  fileSystems."/srv/torrents" = {
    device = "/dev/disk/by-label/WD";
    fsType = "ntfs3";
    options = [
      "uid=1000" # your account (id -u)
      "gid=100" # the users group
      "nofail" # boot without the drive
      "x-systemd.device-timeout=10s"
    ];
  };

  # Start only once the drive is there.
  systemd.services.qbittorrent.unitConfig.RequiresMountsFor = [ "/srv/torrents" ];
}
#+end_src

** Reaching the server: nix/server/ssh.nix
:PROPERTIES:
:header-args:nix: :tangle nix/server/ssh.nix

SSH from the laptop (=ssh server.local=), with keys only. The name
=server.local= comes from avahi, which the core role already runs; here it

*Before the first switch* on the server, put the laptop's public key
(=cat ~/.ssh/id_ed25519.pub= on the laptop) in =keys=. Without a key you

#+begin_src nix

# nix/server/ssh.nix: SSH with keys only, and the name server.local.
{ username, ... }:

{
  services.openssh = {
    enable = true;
    openFirewall = true;
    settings = {
      PasswordAuthentication = false;
      KbdInteractiveAuthentication = false;
      PermitRootLogin = "no";
    };
  };

  users.users.${username}.openssh.authorizedKeys.keys = [
    # "ssh-ed25519 AAAA... mathijs@laptop"
  ];

  services.avahi.publish = {
    enable = true;
    addresses = true; # answer to server.local
  };
}
#+end_src

** Moving the torrent list to the server

qBittorrent keeps one =.torrent= and one =.fastresume= file per torrent in
its =BT_backup= folder; the =.fastresume= file holds the statistics (total
uploaded, time active, the save folder). Moved together, they bring every
torrent across with its history. On Windows the folder is
=%LOCALAPPDATA%\qBittorrent\BT_backup=.

The save folders inside the =.fastresume= files are Windows paths
(=E:\Torrents=). =qbt_migrate= rewrites them:

1. On Windows: quit qBittorrent, and copy =BT_backup= to a USB stick or the
   WD drive.
2. On the server: =sudo systemctl stop qbittorrent=.
3. Copy the files into the service's =BT_backup= folder
   (=/var/lib/qBittorrent/qBittorrent/data/BT_backup=; =ls= to check the
   exact path).
4. Rewrite the paths with =qbt_migrate=, run from a temporary Python
   environment by =uvx=. If the WD drive was =E:= on Windows (its root
   becoming =/srv/torrents=), first look at what would change:
   =uvx qbt_migrate -b /var/lib/qBittorrent/qBittorrent/data/BT_backup -e E: -n /srv/torrents -t Linux -d=
   (=-b= the folder, =-e= the old start of the paths, =-n= the new one,
   =-t Linux= turns =\= into =/=, =-d= only shows). Then run the same
   command without =-d=; it saves a zip backup first. Leave out a trailing
   =\= after the drive letter.
5. =sudo systemctl start qbittorrent=, open =http://server.local:8080=,
   and let qBittorrent check a few torrents (right-click, /Force recheck/)
   to confirm it finds the files.

The categories and tags are in =categories.json= next to the
configuration; copy it as well if you use them.
